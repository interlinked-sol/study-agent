# eval/ — 评测金标准与回归记录

## 这是什么

给 prompt 迭代提供「标准答案」的地方。没有它，改 prompt 后只能说「感觉变好了」；
有了它，才能报出「召回率 62%→89%」这种数字。

## 建立金标准（每章一个文件）

1. 跑一次管线，拿到 `build/考点清单-<章节>.md`。
2. **人工逐条核对**（对照原课件）：删掉编错的、补上漏掉的，
   留下 15~20 条「本章必须有」的考点。
3. 存为 `eval/<章节>-golden.md`，**冻结**——之后只许改输出，不许改金标准。

⚠️ 两条红线：
- 金标准必须人工核对，**禁止直接拿 AI 输出充当**（循环论证，分母不可靠）。
- 金标准冻结后不与输出对账时修改它——尺子不能迁就东西。

## 回归流程（每次改 prompt 后）

1. 删掉 `build/.cache/`（缓存 key 不含 prompt，不清会命中旧结果）。
2. 重跑同一章：`uv run study-agent run <pdf> --course ... --chapter ...`
3. 对照 golden 数覆盖了几条 → 召回率 = 覆盖数 ÷ golden 总数。
4. 记入 `eval/history.md`：日期 / prompt 版本 / 召回率 / 备注。涨了保留，跌了回滚。

## 备选：合成测试集（零标注成本）

拿正常课件人为注入已知问题（删段落、改错概念），跑管线看检出率。
问题是你注入的，答案 100% 确定。适合补充召回率之外的「检出」类指标。
